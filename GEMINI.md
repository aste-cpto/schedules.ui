# Контекст Проєкту: Schedules UI

Цей файл містить архітектурні та стилістичні правила для проєкту `schedules.ui`. Він автоматично завантажується агентом у кожній сесії для збереження контексту.

## Технологічний Стек
- **Фреймворк:** React 19 + TypeScript + Vite
- **Стилізація:** Tailwind CSS (v4) + SCSS (головні стилі в `src/styles/`)
- **Роутинг:** React Router v7
- **Іконки:** `lucide-react`
- **Drag & Drop:** `@dnd-kit`

## Архітектурні Патерни
- **Структура директорій:**
  - `src/ui/`: Спільні UI-компоненти (наприклад, `Button`, `Input`, `ModalLayout`, `TablePaginationBar`).
  - `src/pages/`: Компоненти сторінок. Кожна сторінка має власні `components` та `hooks` (наприклад, `src/pages/SchedulesPage/`).
  - `src/services/`: Сервіси для роботи з API (наприклад, `schedulesService.ts`).
  - `src/hooks/`: Глобальні хуки для бізнес-логіки.
  - `src/mappers/`: Мапери для перетворення DTO з API у клієнтські моделі (domain models).
  - `src/types/`: TypeScript-типи (типи API лежать у `src/types/api/`).
  - `src/contexts/`: React-контексти (`AuthContext`, `ModalGuardContext`).

- **Робота з даними (Data Fetching):**
  - **НЕ ВИКОРИСТОВУЮТЬСЯ** сторонні бібліотеки типу React Query, Redux чи Zustand.
  - Дані завантажуються через кастомні хуки (наприклад, `useSchedules.ts`), які використовують `useState` та `useCallback`.
  - Для автоматичного оновлення списків використовується хук `useAutoListFetch`.
  - **Modal Guard:** Автоматичний рефетчинг призупиняється, якщо відкрито модальне вікно (через `isModalOpen` з `useModalGuard`).

- **Обробка помилок та Сповіщення:**
  - Помилки API обробляються через утиліту `getErrorMessage` (`~/lib/formatApiError`).
  - Для сповіщень використовується хук `useToast` (`~/ui/toast/useToast`).

- **Імпорти:**
  - Завжди використовуйте аліас `~/` для абсолютних імпортів із папки `src/` (наприклад, `import { Button } from '~/ui/Button'`).

## Правила Написання Коду (Guidelines)
1. **Мова UI:** Усі тексти, які бачить користувач (тексти кнопок, модалок, повідомлення про помилки тощо), мають бути написані **українською мовою**.
2. **Мова Коду:** Назви змінних, функцій, файлів, типів та коментарі в коді пишуться **англійською мовою**.
3. **UI Компоненти:** Перед створенням нового компонента перевіряйте папку `src/ui/`. Перевикористовуйте існуючі компоненти (`Button`, `Input`, `Select`, `DatePicker`, тощо).
4. **Стилізація:** Використовуйте utility-класи Tailwind CSS. Уникайте написання кастомного CSS, якщо це можна вирішити за допомогою Tailwind.
5. **Іконки:** Використовуйте іконки з бібліотеки `lucide-react`.
